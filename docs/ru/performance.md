# Производительность

Базовые данные, методика измерений и правила сопровождения: [BASELINE](../../tests/bench/BASELINE.md). Воспроизведение:

```bash
uv run --with tomli --with tomlkit python tests/bench/bench.py --compare --iterations 500
```

## Итоги (измерено на v0.1.0; 0.1.1 не затрагивает горячие пути движка)

| Метрика | Значение | Сравнение |
|---|---|---|
| Разбор | 1.73× / 1.94× tomli (два корпуса) | в 5.8–6.4 раза быстрее tomlkit 0.15.1 |
| `dumps` без правок | ~O(1) | склейка срезов исходника |
| `dumps` с правками | O(размера правки) | ре-рендеринг только «грязных» узлов |
| Резидентная память | 0.67× tomlkit (бюджет ≤0.7×) | выше tomli (цена точности) |
| Соответствие | toml-test 1.0: все 208 валидных файлов проходят побайтово точно, все 501 невалидный файл отклоняется | тест tomlkit на невалидных файлах: 208/214 |

## Как это устроено

1. **Рендеринг из срезов исходника**: нетронутые узлы рендерятся напрямую из `source[span]`; `dumps` неизменённого документа — ~O(1)
2. **Материализация при правке**: данные форматирования строятся только при записи узла — путь чтения не платит ничего за стиль
3. **Однопроходный разбор с диспетчеризацией по символам**: сопоставление блоков прекомпилированными regex, без посимвольных циклов и regex-штормов на каждый токен
