# 效能

基線資料、測量方法與維護規則見：[BASELINE](../../tests/bench/BASELINE.md)。重現方式：

```bash
uv run --with tomli --with tomlkit python tests/bench/bench.py --compare --iterations 500
```

## 摘要（v0.1.0 實測；0.1.1 未觸碰引擎熱點路徑）

| 指標 | 數值 | 對比 |
|---|---|---|
| 解析 | tomli 的 1.73× / 1.94×（兩個語料） | 比 tomlkit 0.15.1 快 5.8–6.4× |
| 未編輯的 `dumps` | ~O(1) | 來源切片拼接 |
| 編輯後的 `dumps` | O(編輯量) | 只重新渲染變動節點 |
| 常駐記憶體 | tomlkit 的 0.67×（預算 ≤0.7×） | 高於 tomli（保真的代價） |
| 一致性 | toml-test 1.0：208 個有效檔案全部以位元組級一致通過，501 個無效檔案全部被拒 | tomlkit 無效檔案自測：208/214 |

## 運作原理

1. **來源切片渲染**：未觸碰的節點直接從 `source[span]` 渲染；未編輯文件的 `dumps` 約為 O(1)
2. **編輯時具體化**：格式資料只在節點被寫入時才建立——讀取路徑的樣式成本為零
3. **單趟字元分派解析**：以預編譯的正規表示式做區塊匹配，沒有逐字元迴圈，也沒有逐權杖的正規表示式風暴
