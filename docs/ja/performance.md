# パフォーマンス

ベースラインデータ、測定方法、運用ルール：[BASELINE](../../tests/bench/BASELINE.md)。再現：

```bash
uv run --with tomli --with tomlkit python tests/bench/bench.py --compare --iterations 500
```

## 概要（v0.1.0 で実測；0.1.1 はエンジンのホットパスに触れていません）

| 指標 | 値 | 比較 |
|---|---|---|
| 解析 | tomli の 1.73× / 1.94×（2 コーパス） | tomlkit 0.15.1 より 5.8–6.4× 高速 |
| 未編集の `dumps` | 約 O(1) | ソーススライス結合 |
| 編集後の `dumps` | O(編集サイズ) | ダーティノードのみ再レンダリング |
| 常駐メモリ | tomlkit の 0.67×（予算 ≤0.7×） | tomli より大きい（忠実性のコスト） |
| 準拠 | toml-test 1.0：valid 208 すべてバイト一致で合格、invalid 501 すべて拒否 | tomlkit invalid セルフテスト 208/214 |

## 仕組み

1. **ソーススライスレンダリング**：未編集ノードは `source[span]` から直接レンダリング；未編集ドキュメントの `dumps` は約 O(1)
2. **編集時に具現化**：フォーマットデータはノードが書き込まれるときだけ構築 — 読み取りパスはスタイルコストゼロ
3. **シングルパス文字ディスパッチ解析**：事前コンパイル正規表現ブロックマッチング、文字単位ループなし、トークンごとの正規表現ストームなし
